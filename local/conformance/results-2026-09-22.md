# FIDO2 Server Conformance record — 2026-09-22

FIDO Conformance Tools 1.9.1 was run through the installed macOS application. **Both native and Wasm passed all 155 mandatory cases.** Results were not submitted for formal certification.

| Target | Passed | Failed | Suite time |
| --- | ---: | ---: | ---: |
| Native Rust example | 155 | 0 | 47.49 s |
| Wasm in Node | 155 | 0 | 48.35 s |

The final run followed hardening of required certificate Basic Constraints, unsupported name/policy constraints, and explicit null tokenBinding rejection. Rebuilt source and binary hashes are in the [run manifest](manifest-2026-09-22.json). All Server Tests were selected, 14 extra optional algorithm/attestation cases were off, AUTOSCROLL was off, URL was `http://localhost:8080`, RP ID was `localhost`, and each target started with fresh memory state. The GUI listed 169 including the 14 unselected cases. No mandatory assertion case was hidden by a before-all setup failure. These suite totals are not a speed benchmark.

The test API offered ES256, Ed25519, RS256, and RS1 and reflected requested UV, resident key, attestation, and extensions in options. Verification used the trusted stored ceremony policy; product defaults were unchanged. The shared Rust core verified certificate-backed packed, U2F, TPM 2.0, and MDS. The adapter did not rewrite attestation to `none`, skip signatures, or fill in a missing user handle.

One of five MDS BLOBs yielded 100 entries after signature, chain, and CRL verification; the other four were rejected. No root from a failed BLOB was trusted. A wrong-chain BLOB also led to a disallowed CRL URL, and independent fixtures covered chain rejection. Test roots were configured in the adapter only.

Independent fixtures included 21 packed/U2F/TPM registration cases and 9 MDS cases. At this run, 17 shared core tests and two compile-fail checks ran on native/Wasm; local browser/D1 integration, Clippy, formatting, and design checks also passed. Native core line coverage was 86.60% and region coverage 79.25%. The whole Worker Wasm was 597,346 bytes raw and 235,539 gzip, not a WebAuthn-only size. Cargo audit used the narrowly documented RSA public-verification exception for RUSTSEC-2023-0071 and reported no additional finding; see [ADR 0008](../../docs/adr/0008-webauthn-conformance.md).

## Development-run history

The earlier measurements below document gaps that were later closed; they are not the final capability state.

| Stage | Wasm passed/failed, time | Native passed/failed, time | Main limitation |
| --- | --- | --- | --- |
| Initial corrected adapter | 84/22, 38.22 s | 84/22, 34.21 s | Four assertion groups unreachable after registration before-all failure; fixed required policy and limited formats |
| After ES256 packed self | 87/19, 41.77 s | 87/19, 32.26 s | Certificate-backed formats, algorithms, and assertion setup still missing |
| After trusted policy and Ed25519/RSA | 91/15, 35.94 s | 91/15, 37.03 s | Certificate/MDS formats and registration-dependent assertions still incomplete |
| Final full run | 155/0, 48.35 s | 155/0, 47.49 s | Mandatory target complete under stated conditions |

An even earlier 110-pass/45-fail connection attempt was discarded because the adapter converted requested direct attestation to `none`, changing suite-generated input. Negative tests may pass merely because an unsupported format is rejected; a pass count alone is not the implemented-feature count. Initial fixed UV/resident settings could not satisfy preferred/discouraged option tests. The first run also exposed an invalid tokenBinding acceptance case; later independent regression inputs and the final hardening addressed tokenBinding behavior.

ES256 packed self added three passing cases: self-algorithm, valid packed self, and accepting self when `none` was requested. After that stage the 19 failures grouped as one options-policy, three missing key algorithms, five packed full, three U2F/TPM, one MDS, two successful registration variants, and four unreachable assertion preparations. The later trusted-policy/Ed25519/RSA stage added registration options and RS256/RS1/Ed25519 self-signature success while leaving certificate and assertion setup work. The product default stayed ES256/UV required/discoverable/`none` throughout.
