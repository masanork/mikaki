# Product authorities and test models

The Rust OP remains the production authority for OIDC/WebAuthn HTTP behavior and owner ciphertext commits. `src/token.rs` owns ordinary/native client authentication, bounded request decoding, assertion reservations, authorization-code exchange and reuse revocation. `src/lib.rs` wires routes and remaining authorization orchestration; `passkey_login.rs`, `enrollment.rs`, `logout.rs` and `dpop.rs` retain their distinct responsibilities. The Identity/Wallet implementation is integrated in main by PR #105 and has separate product, device and deployment qualification gates.

| Source | Role | Evidence it provides |
| --- | --- | --- |
| `crates/auth`, `crates/oidc`, `crates/webauthn` | Portable Rust rules and cryptography | Core/native/Wasm invariants |
| `crates/worker/src` and `migrations` | Product transport and durable authorization | Real Worker contract/browser tests |
| `crates/identity` | Linked-document credential, issuer and Wallet protocol rules | Rust and protocol-fixture tests; not production or device qualification by themselves |
| `crates/worker/src/identity.rs` | Identity intake, owner consent, issuance, presentation, UserInfo and lifecycle routes | Actual Worker/workerd tests; feature activation and deployment are separate gates |
| `crates/worker/service` | OP-owned named storage entrypoints | Storage privilege and atomicity boundary |
| `crates/agent-worker` | Accepted TS Agent domain authority and MCP/HTTP adapters | Agent SDK/workerd/browser qualification |
| `crates/userinfo-claim-worker` | Recipient secret custody, envelope validation/decryption | Native crypto and live Secrets Store plus service-binding tests |
| `local/op` and `local/test` | Disposable Node demonstration/model | Model/UI development; not production Rust qualification |
| `design/oidc` and isolated probes | Schema/specification or interoperability models | Their stated layer/profile only |
| `scripts/test_*_sql.test.ts` | Executable SQL invariants | Actual included product SQL where stated; otherwise design-model checks |

Product SQL should be reused directly where the contract is identical. ClaimStore imports the same active-release and conditional-audit SQL as the recipient Rust implementation. Agent's capability catalog is generated by static analysis of actual product `.prepare` calls, accepts only one fixed statement per capability and restricts mutations to Agent tables. `npm run check:service-authority` rejects drift and type-checks the entrypoints. A catalog change requires review of the resulting capabilities and their parameters.

Node models deliberately have different adapters and fixture controls; they are not imported into the Rust production handler. Do not duplicate a security fix into a model and treat model success as product evidence. Run the corresponding real Worker test and retain profile-specific contracts such as [code reuse](code-reuse-policy.md). New portable shared rules should move into a core or shared SQL contract when that preserves the protocol boundary, rather than forcing all profiles into one HTTP state machine.

The Identity implementation is merged source from PR #105; its local CI evidence does not establish production activation. The related refactor and gates were source-reviewed on 2026-10-05. See [test quality](test-quality.md) for broader coverage and deployment limits.
